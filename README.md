# workbuddy-client-outreach-sop

> **分类**：原创 / AI 打磨 ｜ **文件数**：5 ｜ **仓库目录**：`workbuddy-client-outreach-sop`

## 📌 简介

一份 **WorkBuddy 客户建联 SOP 与分角色话术卡**（.docx，4300+ 字），
把「第一次接触客户」这件最靠临场发挥的事标准化成可复用的流程与话术。

配套一个生成脚本 `build_sop_docx.py`（`python-docx`）——文档是脚本生成的，
**改内容重跑脚本即可重新排版**，不会因为手改 Word 导致格式逐渐崩坏。

## 🎯 适用场景

- 销售 / 售前第一次接触客户，需要一套**可复用的建联流程**而不是各凭手感
- 面对不同角色（决策人 / 业务负责人 / IT）需要**不同的开场话术**
- 新人入职培训：给一份照着就能做的 SOP，而不是让他自己摸索
- 定期复盘时，把临场发挥好的话术沉淀回 SOP

## ✨ 功能特性

- **流程标准化**：建联前准备 → 首次接触 → 需求探询 → 后续跟进，每步有明确动作与产出
- **分角色话术**：同一件事，对决策人讲价值、对业务负责人讲效率、对 IT 讲集成与安全
- **可直接发放**：成品是排版好的 .docx，打印或转 PDF 都行
- **内容与排版分离**：`build_sop_docx.py` 是生成器，内容改在脚本里，排版不会崩

## 🧭 文档内容结构

`build_sop_docx.py` 生成的文档按「流程 + 分角色话术」组织：

| 模块 | 内容 |
|---|---|
| **建联前准备** | 客户背景调研清单、可承诺与不可承诺边界、材料准备 |
| **首次接触** | 开场白结构、破冰点选择、第一通电话/第一条消息的写法 |
| **分角色话术卡** | 同一方案对决策人 / 业务负责人 / IT 三种讲法 |
| **需求探询** | 提问清单：现状 → 痛点 → 量化 → 优先级 |
| **后续跟进** | 跟进节奏、常见异议应对、什么时候该放弃 |

> 完整内容请直接打开 `docs/` 下的 .docx —— 话术卡里有具体的句子模板。

## 🔬 工作原理

```text
scripts/build_sop_docx.py
  ├─ 内容数据段（各章节的标题 / 正文 / 表格数据）
  └─ 排版段（python-docx：字体 / 表格 / 页眉页脚 / 分页）
          ↓
   docs/WorkBuddy客户建联SOP与话术卡.docx
```

脚本里用了 `docx.shared.Cm/Pt` 与 `WD_TABLE_ALIGNMENT` 做表格对齐，
把「话术卡」做成表格形式，方便打印后贴在工位上对照。

## ❓ 常见问题

**Q：话术卡是「照着念」的吗？**
不是。话术给的是**结构与关键句**，照念会很僵。正确用法是把结构记住、
关键句内化，临场按对方反应调整。

**Q：面向不同行业要改很多吗？**
行业相关的只是「痛点举例」那部分，流程与话术骨架是通用的。
建议按行业各做一份变体，而不是一份文档硬套所有行业。

**Q：为什么用脚本生成而不是直接写 Word？**
因为 SOP 会反复迭代。脚本生成的文档格式始终一致，
不会出现「改了 10 次后标题字号有 3 种」的情况。

**Q：能转成 PPT 用于内部分享吗？**
可以。文档结构本身就是按「流程 → 话术卡」分的，天然适合拆成页。

## ⚠️ 注意事项

- 话术里**不要写具体报价**——报价走正式方案，话术卡里只谈价值与边界
- 改内容请改 `build_sop_docx.py` 然后重新生成；直接改 docx 的话，
  下次重跑脚本会覆盖你的修改
- 话术需结合当地合规要求使用（尤其涉及承诺、数据处理的表述）
